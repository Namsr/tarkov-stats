# Первый полноценный UI на Rust: статистика Arena

Цель миграции — весь сайт на Rust, включая HTTP, данные, кеши, SSR и интерактивный UI, с удалением Node/Next из конечного runtime. Первый UI-срез: `/population/arena` со всеми текущими возможностями. Перенос одного API или статичной служебной страницы этой цели не заменяет.

Исходный анализ выполнен на `b71bbc7` от 26 октября 2026 года. Реализация первого среза и её текущие проверки описаны в [rust-arena-ui.md](rust-arena-ui.md). Ниже сохранены границы и критерии переноса; наличие кода само по себе не доказывает выполнение каждого критерия. Локальные измерения не заменяют проверку production. Доступ к рабочему сайту и VPS для исходного анализа не использовался.

## Почему Arena

| Кандидат | Фактическая загрузка и зависимости | Вывод для первого среза |
| --- | --- | --- |
| Главная | `app/page.tsx` отдаёт клиентский `components/HomePage.tsx`. Первый effect `/api/home/showcase` выбирает AID/режим/цикл (строки 87–107), затем стартуют profile/cohort/timeline (111–184). Профиль уже публикуется отдельно от вторичных данных. Есть поиск, избранное в сравнении, риск, история и leaderboard. | Удаление начального каскада перспективно, но полная страница требует перенести много ещё не нативных сервисов. Rust `/api/home/showcase` полезен как отдельный источник будущего SSR. |
| Профиль | `app/player/[[...segments]]/page.tsx` валидирует маршрут и выбирает компонент, но обычные данные профиля не передаёт в SSR. `RegularPlayer.tsx:150–275` и `SeasonalPlayer.tsx:195–338` берут начальное состояние из браузерного кеша и загружают profile API. Далее нужны refresh, риск/polling, история, radar/cohort, достижения, навыки, избранное, жалобы; Arena добавляет Axis. | Сильный пользовательский кандидат, но слишком широкая первая граница для сохранения всей функциональности. Нельзя считать переносом профиля только шапку и несколько карточек. |
| Статистика Arena | `app/population/[mode]/page.tsx` переиспользует `app/average/[mode]/page.tsx`; Arena выбирается в строке 31 последнего файла. `components/ArenaAverage.tsx:612–733` содержит весь экран. Сейчас URL читается после mount, затем идут overview, постоянный контекст гистограммы и выбранная выборка (`487`, `530`, `636–676`). | Ограниченный, но содержательный экран. Расчёт `arena_population` уже есть в `rust/cohort-worker/src/arena.rs`; для него не нужны запросы к внешнему Tarkov API. Есть возможность показать полезные числа в первом HTML. |

Это оценка объёма и каскадов по коду, а не доказательство, что Arena имеет наибольший пользовательский трафик или самый высокий выигрыш по задержке. `PERFORMANCE.md:40–53` прямо отмечает отсутствие сопоставимых браузерных LCP/INP/гидратации. Его размеры старой сборки нельзя выдавать за текущие замеры или экономию Rust.

## Граница законченного среза

1. Rust обслуживает HTML `/population/arena`, включая параметры, trailing slash и ошибки. Старый `/average/arena` сохраняет постоянный redirect на `/population/arena` с query; существующий `next.config.ts:83–88` задаёт этот alias. Фрагмент URL сохраняет браузер, сервер его не получает.
2. Rust обслуживает используемый страницей вариант `/api/average?mode=arena`: разбор и валидацию параметров, стандартные публикации, динамический кеш, ошибки/заголовки, нативный расчёт. Остальные режимы `/api/average` остаются на прежнем backend до своего переноса. Caddy направляет только согласованный Arena-вариант; дубликаты query и неизвестные параметры покрываются дифференциальными тестами.
3. HTML содержит выбранный по URL режим, число просканированных аккаунтов, числа по пяти игровым режимам, пять метрик, размер выборки, гистограмму и её подписи. После загрузки WASM работают все те же переключатели и диапазоны. Не допускается новая пустая оболочка, в которой данные появляются только после обязательного клиентского fetch.
4. Общая шапка, подвал, FAQ, переключатели языка/темы, вход/выход, уведомление поддержки и телеметрия сохраняются. Их Rust/WASM-реализация может временно обращаться к существующим same-origin API. Это явная переходная зависимость от Next; страница с такими запросами ещё не означает завершение всей миграции. Полное удаление Node требует последующего переноса auth/favorites/support/analytics и остальных маршрутов.

## Архитектура

Существующие Axum HTTP-сервер и Rust compute child остаются основой. Предлагаемый UI — SSR с небольшими Rust/WASM islands, например Leptos с Axum-интеграцией. [Официальное введение](https://book.leptos.dev/getting_started/index.html) описывает SSR с последующей WASM-гидратацией, а [руководство islands](https://book.leptos.dev/islands.html) — гидратацию только интерактивных компонентов и передачу серверного содержимого без включения его кода в WASM. Это соответствует странице с большим статичным каркасом и локальной интерактивностью.

Варианты: ручные Rust-шаблоны плюс собственный WASM DOM-код потребуют поддерживать два способа рендера карточек/ошибок и сложную синхронизацию состояния; целиком клиентский WASM SPA сохраняет ожидание загрузки runtime до данных; полная гидратация всего документа переносит в браузер лишний код. Islands позволяют использовать один Rust-компонент для SSR и интерактивного участка. Они сами по себе не гарантируют меньший payload или быстрый старт: это проверяется сравнением сборок и браузерных трасс. Конкретные совместимые версии Leptos/Axum/cargo-leptos и feature flags следует подтвердить перед добавлением зависимостей; пакеты этим планом не добавляются.

Предлагаемые файлы реализации:

- `rust/ui/`: Cargo manifest с отдельными SSR/hydrate features, общие типы состояния Arena, SSR document/layout, Arena dashboard, islands для фильтров/гистограммы и общих элементов сайта. Серверные SQLite/секреты не попадают в WASM-зависимости.
- `rust/backend/src/`: HTML/static routes, Arena average handler/service и чтение публикаций; обобщение текущего bounded compute/cache слоя только на два действительно поддерживаемых контракта. Сейчас `compute.rs:34–60` проверяет именно Seasonal `{available,result}`; Arena возвращает другой объект. Нельзя пропускать его через старый валидатор или ослаблять проверку до любого JSON. Проверять `filterIdentity`, ожидаемые типы и идентичность результата до кеширования.
- `rust/cohort-worker/src/arena.rs`: переиспользуется текущий расчёт `arena_population`; UI не дублирует статистическую математику. Не заменять killable child неограниченным `spawn_blocking`. Сохранить текущие очередь, общий deadline запроса и ограничения памяти/ответа.
- `components/ProfileModeSwitch.tsx` и остальные найденные ingress к `/population/arena`: переход через границу Rust/Next; `ops/Caddyfile`, конфигурация запуска и Docker: единый opt-in для HTML и Arena API, статические ресурсы Rust, быстрый откат на прежние обработчики. Убедиться, что routing не перехватывает другие варианты API.
- Общие источники оформления/переводов остаются `app/globals.css`, `lib/i18n/dictionary.ts`, `public/`; отдельная сборка публикует CSS и хешированные Rust WASM/loader assets независимо от `/_next/*`. Tailwind utilities должны извлекаться и из Rust-шаблонов, иначе существующие классы исчезнут из CSS. Не полагаться на случайный CSS chunk сборки Next. Временный инструмент сборки CSS не должен требовать Node в runtime; удаление Node из финального build-процесса проверяется отдельно.

SSR и API обращаются к одному Arena service/cache, без HTTP-запроса сервера к самому себе и без обхода квот. На hit данные рендерятся сразу; на cold path не ждать auth/support/телеметрию или прогрев всех режимов перед показом выбранной выборки. Стратегию streaming против ожидания выбранной выборки выбрать по cold/hit измерениям, не обещать улучшение TTFB заранее. При streaming данные должны приходить в исходном HTML-потоке, без обязательного второго клиентского запроса. Сериализованное начальное состояние исключает повторный fetch того же свежего ответа при гидратации.

Сохранить публичный storage contract `app/api/average/route.ts:78–165`, `lib/arena-average-cache.ts`, `lib/average-publication.ts`, `lib/average-dynamic-cache.ts`: parser/schema version, revision-aware invalidation, стандартные публикации, `publicationOnly`, last-good/stale и retry. Стандартная публикация и фильтрованная выборка с `minMatches=10` — разные ключи. Существующее требование предварительно инициализированных SQLite остаётся явным; SSR не создаёт таблицы данных и не выдаёт отсутствие базы за настоящую нулевую выборку. Общий бюджет двух backend в период миграции измеряется отдельно.

## Совместимость UI

- **Граница Next/Rust.** `ProfileModeSwitch.tsx:143–170` использует Next `<Link prefetch scroll={false}>`. Это RSC/client navigation, который Rust HTML не реализует. При opt-in все входящие ссылки и программные переходы в Rust-срез должны выполнять document navigation, без Next prefetch. На стороне Rust ссылки в ещё не перенесённые страницы тоже обычные. Проверять переход из работающего Next UI, а не только прямое открытие URL. Не эмулировать RSC. Аудит ingress повторить по `/population`, `page="average"`, mode helpers и программным router-переходам.
- **Общая оболочка.** Воспроизвести `app/layout.tsx:52–74`, `SiteHeader.tsx`, `SiteFooter.tsx`, `AuthButton.tsx`, `SupportHeaderNotice.tsx`, `FaqWidget.tsx`, `SkipLink.tsx`, `NavigationPendingTracker.tsx`, `PageviewBeacon.tsx`, `PerformanceBeacon.tsx`. Auth API, logout POST, безопасные session cookies и Google flow остаются совместимыми. `lib/favorites/context.tsx` задаёт отдельные loading/unauthenticated/error состояния и глобальное избранное по AID; будущие Rust-потребители не должны изменить это на идентичность режима. Не блокировать данные Arena загрузкой личного состояния. FAQ сохраняет focus trap, inert-фон, Escape и возврат фокуса. Аналитика сохраняет host/DNT/лимиты и не становится условием рендера.
- **Все органы управления.** Пять режимов в текущем порядке; median/trimmed_mean; ось hours/matches; players и пять метрик; независимые фильтры каждого режима, четыре границы, invalid-range, пустые/неизвестные значения. Сохранить имена `arenaMode`, `arenaStatistic`, `arena_<mode>_*`, URL replace/popstate и восстановление после reload. Не добавлять Arena period, которого сейчас нет. Гистограмма использует полный стабильный контекст, карточки — выбранную выборку (`ArenaAverage.tsx:465–607`). Slider показывает draft немедленно, отправляет запрос после завершения взаимодействия; ввод границ поддерживает blur/Enter. Смена режима/параметров отменяет старого потребителя, запоздалые ответы не меняют текущую идентичность, stale не подменяет новые параметры. Формулы геометрии берутся из `lib/arena/average-range.ts` и `lib/histogram.ts`, не из новой приближённой реализации.
- **Дизайн и доступность.** Сохранить DOM-иерархию, классы, CSS variables/dark-light, SVG, grid, scroll, переносы и состояния. `ArenaAverage.tsx` использует 26px минимальную ширину столбца, 6px gap и ResizeObserver; изменение числа bins при resize не должно менять фактические границы выборки. Проверить 360/768/1280px и стороны реальных CSS breakpoints, клавиатуру, touch/pointer cancel, focus-visible, labels/aria-pressed/aria-live, reduced motion. Основные данные доступны без WASM; GET-форма/ссылки дают рабочий запасной путь. Не заменять текущие интерактивные контролы статичной картинкой.
- **i18n и SEO.** Язык SSR как `lib/i18n/server.ts`: валидный cookie `lang`, затем Accept-Language. В обоих языках одинаковые ключи и interpolation fallback; переключение языка не перезапускает статистический расчёт и не теряет выборку. Сохранить cookie, `html lang`, title/description (`lib/i18n/context.tsx:38–47`), headings и доступные имена. SSR читает реальный URL сразу, а не повторяет ограничение прежнего hydration effect. Все строки идут через общий словарь; нельзя вручную развести Rust и TS копии переводов. Локаль чисел должна быть определена одинаково для SSR/WASM, чтобы избежать гидратационных расхождений. Правильные 404/redirect/security headers, экранирование текста/JSON/URL, отсутствие пользовательских данных в общем HTML-кеше. CSP уже разрешает `wasm-unsafe-eval`; не добавлять общий `unsafe-eval` для нового runtime.

## Проверяемая готовность

1. Дифференциальный тест настоящего HTTP Next/Rust на одной синтетической SQLite и одних публикациях: HTML-смысл/данные, query/defaults, redirect/status/methods/headers, cache hit/stale/miss/revision, ошибки/пустая база. Переиспользовать `tests/fixtures/rust-arena-seasonal-data.mjs` и `tests/rust-arena-seasonal.test.mjs`; текущие native parity тесты защищают математику, но не доказывают правильность UI/API кеша.
2. Rust unit checks общей URL/filter/range/format/i18n логики и browser-проверка реальных кликов: deep links всех режимов, запросы из/в Next, reload/back/forward, slider keyboard/pointer, ResizeObserver, смена языка/темы, auth/logout, FAQ/focus, ошибки/retry/stale/отмена. Портировать смысл текущих `tests/arena-ui.test.mjs:171–345`, `tests/mode-switch-cancel.test.ts`, `tests/client-average-request.test.ts`, `tests/i18n-document-meta.test.mjs` и FAQ-проверки `tests/profile-ui.test.mjs:875`; их regex-проверки React-исходников не являются доказательством Rust-поведения.
3. Сравнительные скриншоты RU/EN, dark/light, выбранного/пустого/ошибочного диапазона на названных viewport; отсутствие горизонтального overflow и потери фокуса. CSP без console errors; HTML с полезными числами при отключённом WASM.
4. Один воспроизводимый браузерный baseline до/после: одинаковые CPU/network/viewport, SQLite snapshot, locale и URL; отдельно cold HTTP/cache и hit, несколько повторов. Измерять время до первых полезных чисел и готовности графика к вводу, LCP/INP/CLS, TTFB, JS/WASM/CSS compressed bytes, запросы/повторы, server queue/worker/render time, CPU и peak RSS. P95 API нельзя выдавать за время готовности UI. Ускорение принимается только по сопоставимым результатам без ухудшения ошибок/дизайна/контрактов; численный порог задаётся после baseline, не выдумывается заранее.
5. Smoke запуска и отката: opt-in переводит HTML, его API и assets вместе; default оставляет прежний сайт; процесс Rust не оставляет compute child после остановки. В опубликованном HTML нет `/_next/` скриптов/React runtime. Внешние auth/support/analytics API пока учитываются как переходный Node-зависимый остаток. Финальный общий acceptance всего проекта — пользовательские маршруты и фоновые службы работают после удаления Node/Next, а не только после выключения одного Next handler.
