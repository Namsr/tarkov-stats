# План исправления профилей и миграции с GraphQL

Реализация ведётся поверх `deploy-community-reports`, поскольку эта ветка соответствует интерфейсу на скриншотах.

## 1. Источники данных tarkov.dev

- Профили продолжать читать из публичных снимков:
  - `players.tarkov.dev/profile/{aid}.json`;
  - `players.tarkov.dev/pve/{aid}.json`;
  - `players.tarkov.dev/arena/{aid}.json`.
- Поле `updated` считать временем обновления публичного снимка tarkov.dev.
- Поведение кнопки «Обновить» не менять: она только открывает профиль на tarkov.dev. Live-endpoint защищён авторизацией/Turnstile и недоступен нашему серверу.
- Полностью удалить зависимость от `api.tarkov.dev/graphql`:
  - уровни брать из `json.tarkov.dev/regular/items`;
  - достижения — из `json.tarkov.dev/regular/tasks`;
  - английские названия достижений подставлять из `json.tarkov.dev/regular/tasks_en`.

## 2. Новый JSON-клиент

- Создать общий серверный клиент для запросов к tarkov.dev с заголовками:

```text
Accept: application/json
User-Agent: TarkovStats/0.1 (+https://tarkovstats.ru)
```

- Применить его к новому JSON API, публичным и сезонным профилям, а загрузчик индекса ников привести к той же строке `User-Agent`.
- Браузерный обновлятор профилей оставить без изменений: он использует обычную браузерную сессию.
- Сохранить шестичасовой успешный кэш справочников. Ошибочный или неполный ответ не должен попадать в кэш.

### Уровни

- Читать `data.playerLevels` как непустой массив `{ level, exp }`.
- Проверять целые положительные номера уровней, конечный неотрицательный XP и отсутствие повторяющихся уровней.
- Сортировать по `level`; `exp` трактовать как прибавку XP от предыдущего уровня и вычислять накопительный порог существующей функцией.
- Добавить версионированную локальную таблицу уровней как fallback для холодного запуска при недоступности JSON API.
- Никогда не заменять ошибку загрузки справочника значением уровня `0`.

### Достижения

- Читать `data.achievements` как объект, ключом которого является ID достижения.
- Поле `name` базового ответа трактовать как ключ перевода и разрешать через `tasks_en.data`; при отсутствии перевода использовать `normalizedName`, затем ID.
- Для интерфейса использовать `normalizedRarity` (`common`, `rare`, `legendary`), а не внутреннее значение вида `Achievements/Tab/...`.
- Сохранить текущие поля процентов завершения и существующий `Map<id, metadata>`, чтобы потребители API не изменились.

## 3. Уровень игрока

- Для regular, PvE и сезонных профилей вычислять уровень из `info.experience` через новый справочник.
- Arena не переводить на обычную шкалу уровней без подтверждённого соответствия Arena XP этой шкале.
- При недоступности внешнего JSON использовать локальный fallback.
- Пересчитывать и обновлять уровень при свежем профиле; ранее сохранённые строки исправляются естественно при следующем обновлении профиля.
- Проверочный пример: `2 935 114 XP` должен давать уровень 36 по текущей таблице.

## 4. Профиль без статистики выбранного режима

- Применять специальное состояние только к подтверждённому `mode_profile_unavailable`; ошибки `429/502/503` оставить обычными ошибками загрузки.
- В ответ `/api/player/profile` добавить необязательное поле:

```ts
profileSummary?: {
  nickname: string;
  side?: string;
  prestige?: number;
}
```

- Формировать его из первого сохранённого снимка того же аккаунта в порядке regular → PvE → Arena, исключая недоступный режим.
- Не подмешивать статистику, `profileUpdatedAt` или `lastPlayedAt` другого режима. Если снимков нет, показывать только ID аккаунта.
- На клиенте сохранить полноценную шапку, действия и переключатель режимов.
- Четыре верхние карточки оставить с обычными подписями, но значением `?`.
- Вместо радара и риска читерства показать одну панель с инструкцией обновить кэш и существующей ссылкой на tarkov.dev.
- Не монтировать рейды, прогрессию, навыки, достижения и остальные нижние секции, чтобы не запускать запросы на основе отсутствующей статистики.

## 5. Интерфейс профиля

- Разместить «Обновить», «В избранное» и «Отметить как подозрительный» в одной строке с одинаковой верхней границей и высотой кнопок.
- Счётчик отметок и предупреждение об устаревшем профиле перенести во вспомогательную строку под соответствующей кнопкой.
- На узких экранах разрешить перенос кнопок, сохраняя их одинаковую высоту и порядок.
- Полностью убрать с главной блок «Добровольная помощь / Помощь посетителей».
- Компоненты, API, таблицы и конфигурационные флаги помощи не удалять — они понадобятся для будущих условий показа.
- Все новые тексты, статусы, `title` и `aria-label` добавить в английский и русский словари.

## 6. Совместимость и обработка ошибок

- Сигнатуры `getPlayerLevels()` и `getAchievements()` сохранить.
- Успешный формат `/api/player/profile` не изменять; `profileSummary` добавлять только к структурированной ошибке отсутствующего режима.
- Ошибка одного справочного endpoint не должна ломать загрузку самого профиля:
  - уровни используют локальный fallback;
  - достижения используют последний успешный кэш, а при его отсутствии — ID вместо имени.
- Логировать источник справочника (`json`, `memory-cache`, `local-fallback`) и ошибки валидации без содержимого профиля игрока.
- Существующие ограничения частоты запросов и пятиминутный кэш профилей сохранить.

## 7. Тестирование

- Проверить разбор и валидацию `data.playerLevels`, сортировку и накопление XP.
- Проверить локальный fallback при сетевой ошибке, HTTP-ошибке и повреждённом JSON.
- Проверить граничные значения уровней и пример `2 935 114 XP → 36`.
- Проверить преобразование объекта достижений в `Map`, английские переводы, `normalizedRarity` и fallback названия.
- Статическим тестом подтвердить отсутствие обращений к `api.tarkov.dev/graphql`.
- Проверить единый проектный `User-Agent` на всех серверных запросах к tarkov.dev.
- Проверить `mode_profile_unavailable` со снимком другого режима и без него.
- Проверить, что четыре карточки показывают `?`, а радар, риск и нижние секции не монтируются.
- Проверить отдельное поведение для `429/502/503`.
- Визуально проверить выравнивание кнопок на desktop и мобильной ширине.
- Проверить отсутствие блока помощи на главной.
- Запустить `npm test`, `npm run i18n:check`, `npm run lint` и production build.
- После развёртывания выполнить smoke-проверку JSON API с нового окружения и убедиться, что запросы с проектным `User-Agent` не блокируются.

## Допущения

- Кнопка обновления и внешний процесс обновления кэша tarkov.dev остаются без изменений.
- Уровни regular и PvE используют одну таблицу; Arena исключена до подтверждения шкалы XP.
- Интерфейс при отсутствии статистики использует вариант «четыре карточки с `?` плюс одна панель с инструкцией».
- Блок помощи скрывается без удаления реализации и без введения временного условия показа.
